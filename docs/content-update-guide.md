# Content-update guide

The syllabus (`Intro-Global-Capital-Markets-Syllabus.md`) is the **single source of truth**. The app
renders whatever the pipeline extracts from it; you never edit course text in the app code.

```
edit syllabus  →  npm run content  →  read docs/content-audit.md  →  npm test  →  (npm run audio)  →  npm run sw  →  deploy web/
```

## 1. Editing the syllabus

Keep the module template the pipeline relies on (it fails loudly if you break it):

| Element | Format the pipeline expects |
|---|---|
| Module heading | `## M<n> — <Title>` inside Part C; parts as `## PART <n> — <TITLE>` |
| Hours | `**Hours:** 8 core (Learn 3 · Practise 4 · Assess 1) + 1.5 Python` (must match the B3 course map) |
| Why it matters | `**Why it matters.** …` paragraph |
| Objectives | numbered list, each starting `**[Know]**`, `**[Understand]**`, `**[Apply]**`, `**[Analyse]**` or `**[Evaluate]**` |
| Subtopics | nested `-` list (2-space indent) |
| Key terms | table with columns `Term` and `Plain-English meaning` |
| Core formulas | optional fenced code block under `### Core formulas` |
| Worked examples | `#### Worked example 4.1 — Title`, `#### Case 1.1 — Title`, `#### Exercise 2.2 — Title`, `#### Track C — Python` |
| Tracks inside examples | `**Problem.**`, `**Track A.**` (or `**Track A — label.**`), `**Track B.**`, `**Track C (Python).**`, `**Meaning.**`, `**Discussion…**` |
| Assessment | `- [ ] Knowledge check: 15 items (≥ 8 numeric)`, `- [ ] Applied task: …`, `- [ ] **Checkpoint exam 1** (Parts 1–2): 40 items, 60 minutes, 70% to pass` |
| Benchmark trace | `**Benchmark trace:** …` |
| References | `[S#]`, `[R#]`, `[D#]` codes in text; definitions in Part H (S/R) and A6 (D) |
| Assessment rules | B5 table (weights, pass marks, item counts, ±tolerance) — the app reads these numbers |

Then run `npm run content`. It writes `web/content/*` and `docs/content-audit.md`, and exits with an error
for structural problems (missing sections, hours that do not add up, undefined reference codes).

## 2. Read the audit

`docs/content-audit.md` (also shown in the app under *About → Transparency report*) lists:

- **errors** — fix before release;
- **warnings** — e.g. historical cases without a primary source, a Wikipedia reference, open errata;
- **info** — e.g. tasks that need live data, practice items described but not supplied.

## 3. Keep the tests green

`npm test` recomputes every worked-example answer. If you change a number in the syllabus, the test
`every checked answer appears verbatim in the extracted syllabus content` fails and names the example.
Update `tests/unit/syllabus-answers.mjs` (and, if the example feeds a quiz generator, the `syllabus`
inputs and `syllabusAnswer` in `web/content/overlays/quiz-numeric.json`). This is deliberate: a changed
number must be re-verified by a person.

If a recomputed value disagrees with the syllabus, record it in `web/content/overlays/errata.json` (the app
shows it beside the example) and correct the syllabus in its next version. Example already recorded:
**WE 13.3** (price at 6% shown as 96.54; correct rounding 96.53) — fixed in syllabus v1.0.1.

## 4. Overlays (authored additions)

Everything not in the syllabus lives in `web/content/overlays/` and must name its syllabus basis.

| File | Contents | Rules |
|---|---|---|
| `quiz-numeric.json` | Numeric item templates: prompt, parameter ranges, `calc` function, `syllabus` inputs and `syllabusAnswer` | The answer is always computed by `web/js/calc.js`; tests check the syllabus inputs reproduce the syllabus answer and that 300 random draws are valid |
| `quiz-items.json` | Conceptual multiple-choice items | Restate one syllabus statement; record `basis` (module + example or section); keep `status` until an SME signs off |
| `interactives.json` | Explorers, sequencers, classifiers, simulations | Explorers start at the example's inputs; sequencer steps and classifier items quote the syllabus; give `basis` |
| `visuals.json` | Diagrams and charts | Every item needs a `description` (text alternative) and `source`; numbers via `calc` where possible |
| `formula-sheet.json` | Extra exam formula-sheet lines for modules without a Core formulas block | Quote formulas used in the syllabus examples |
| `errata.json` | Verification notes | `status: "open"` until the syllabus is fixed |
| `sources.json` | Primary sources for historical cases (G3) | Add only sources you have read; the "Primary source pending" badge disappears automatically |
| `audio.json` | Generated by `tools/build_audio.py` | Do not edit by hand |
| `site.json` | Publisher, report link, repository, licence text | Fill in before public release |

`npm run content` validates overlay references (unknown module or example ids are errors).
`npm test` checks overlays numerically.

### Adding a primary source for a historical case

```json
{ "name": "Barings", "primarySource": { "title": "Report of the Board of Banking Supervision Inquiry into the Circumstances of the Collapse of Barings", "publisher": "Bank of England", "url": "https://…", "accessed": "2026-11-02" } }
```

`name` must match the name in syllabus G3. Rebuild; the case page and the audit update.

## 5. Audio summaries

Audio summaries read each module's *Why it matters*, objectives and key terms. Regenerate after changing
those parts:

```bash
PIPER_BIN=/path/to/piper PIPER_MODEL=/path/to/en_US-ljspeech-medium.onnx npm run audio
```

Only modules whose text changed are regenerated (text hashes are stored). Requires `ffmpeg`. Piper is
MIT-licensed and the voice was trained on the public-domain LJ Speech dataset. Any other open-licensed
engine can be used: update `engine` in `audio.json` so the AI-disclosure page stays accurate.

## 6. Media you add later (video, images)

- Original or openly licensed only (CC BY, CC BY-SA, CC0); record the licence and author.
- Video: captions (WebVTT) and a transcript are required; keep files short and offer them as optional downloads.
- Images and charts: a text description and, for charts, the data as a table.
- Label anything AI-generated.

## 8. Release checklist

- [ ] `npm run content` — no errors; audit warnings reviewed
- [ ] `npm test` and `npm run test:python` pass
- [ ] `npm run test:e2e` and `npm run audit:a11y` pass (for code changes)
- [ ] Audio regenerated if summaries changed
- [ ] `npm run sw` (code changes) — then deploy `web/`
- [ ] Add a `CHANGELOG.md` entry
